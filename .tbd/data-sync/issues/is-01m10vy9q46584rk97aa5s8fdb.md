Deep Transcribe live refinement exposed that an operation created in parameter declaration order and the same operation reloaded from sorted YAML produce different ItemId keys. The source content hash is identical, yet Kash misses the indexed output and reruns every semantic stage. Fix option canonicalization upstream in kash-shell, add a regression test covering serialization/reload, release or install the fix locally, and prove an instructions-only Deep Transcribe rerun starts at overview work.

## Notes

Local Kash source changes have focused regression coverage and pass Ruff plus 10 focused tests. Full native-repository CI will run on the upstream PR because Deep Transcribe’s shared environment has incompatible optional MCP test dependencies.
